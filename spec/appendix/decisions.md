# Appendix C. Decision Log

Design decisions made while drafting the specification, with their rationale.
Each entry records who decided: **(user)** means the project owner chose it
explicitly, and **(proposal)** means the spec authors proposed it and it is
open for review.

## Language

| # | Decision | Rationale |
|---|----------|-----------|
| L1 | wowlua is a **strict superset** of Lua 5.1, with no exceptions **(user)** | Existing addons must compile unchanged. This is why casts use `::` and why there are no word operators such as `as` or `is` in expressions. |
| L2 | **Luau/TypeScript-style inline type annotations** **(user)** | Familiar, concise, and parseable without ambiguity in invalid-Lua positions. |
| L3 | **Gradual typing**, default mode `basic` **(user)** | Existing Lua compiles unchanged. Annotated code gets checked. `--!strict` per file. |
| L4 | **Classes with `end` blocks** and a `constructor` keyword. Instances via `Class.new()` or `Class()` **(user)** | Looks like Lua and is explicit. |
| L5 | **import/export modules** **(user)** | No globals, deterministic load order, and room for a typed WoW standard library. |
| L6 | Build info and debug macros come from **compiler-known modules** (`wowlua:meta`, `wowlua:debug`), with **no `$` sigil** **(user)** | One mechanism (modules). Folding works because import bindings are immutable and compiler-known. |
| L7 | **Core decorators are always in scope**. Framework decorators need imports **(user)** | `@` cannot clash with Lua. Core decorators are language features. |
| L8 | **Decorators:** built-in ones are compile-time. User decorators are runtime functions `(target, ctx) -> replacement?`. Field decorators receive `(nil, ctx)` and their return value is ignored (metadata and registration only) **(user, amended in review R1)** | Powerful enough without the complexity of user compile-time macros. Fields have no value at decoration time. |
| L9 | **Reflection opt-in per class** (`@reflect`). Class identity is always available **(user)** | Keeps output small. Identity is cheap and widely needed. |
| L10 | Syntax sugar: compound assignment, `continue`, `?.`, `??`, backtick interpolation, default parameters, record destructuring **(user)** | Common requests from Lua developers. All lower to Lua 5.1. |
| L11 | Lua 5.3-style bitwise operators, `//`, digit separators, binary literals, `const` **(user)** | All lower to WoW's `bit` library or to literals. |
| L12 | **Enums with braces**: `enum E { A, B }` **(user)** | Mirrors the table it compiles to. |
| L13 | Interfaces, generics, abstract classes, type guards **(user)** | |
| L14 | `import a from "x"` (no braces) and `import _ from "x"` for side effects **(proposal)** | `import {a} from "x"` and `import "x"` are valid Lua calls (superset rule L1). |
| L15 | No explicit type arguments at call sites **(proposal)** | `f<T>(x)` is a valid Lua comparison. Inference and expected types cover the need. |
| L16 | Exported bindings are immutable **(proposal)**. Imports are local copies, except bindings that take part in a run-time-only import cycle, which are read lazily from the module table (see L20) | Cheap imports in the common case. |
| L17 | Widget classes lower to Blizzard-style mixins **(proposal)** | Frames already have a metatable, and the mixin pattern is idiomatic WoW. |
| L18 | Extended escapes (`\x`, `\u{}`) only in backtick strings **(proposal)** | `"\x41"` means `"x41"` in Lua 5.1 (superset rule L1). |
| L19 | **`Secret<T>`** models Midnight secret values. Forbidden operations are flagged, and `issecretvalue` / `canaccessvalue` narrow **(user)** | Catches a whole class of Midnight runtime errors at compile time. |

| L20 | **Automatic load order** from imports plus usage analysis of globals and `ns` fields. Edges are classified as load-time or run-time. The order is a topological sort over load-time edges. Cycles of run-time edges only are allowed (lazy bindings). Cycles containing a load-time edge are errors. Unknown callees count as load-time. `build.load-order` overrides **(user, R1)** | Migrated addons keep working, mutual references are possible, and genuine load-time cycles are caught. |
| L21 | Ambiguous ordering (dynamic global names, several writers): warning, and the affected files keep their source order **(user, R1)** | |
| L22 | Core decorator names **always** resolve to the core decorator **(user, R1)** | Predictable. A user function with the same name must be imported under an alias. |
| L23 | Optional calls (`f?.()`, `a?:m()`) yield **exactly one value** **(user, R1)** | Simple, efficient lowering. |
| L24 | Top-level exported functions, classes and enums are **hoisted** (pre-declared at module top) **(user, R1)** | Mutual references between declarations work. |
| L25 | `::` takes a **full type** including `\|` and `&`. A bitwise operator after a cast needs parentheses **(user, R1)** | Reads naturally for union casts. |
| L26 | Registering decorators (`@global`, `@event`, `@slash`, `@hook`, `export`) capture the **final** decorated value. Transforming core decorators (`@profile`, `@trace`, `@if`, `@debugOnly`, `@inline`) apply innermost **(user, R1)** | `@event @memoize` registers the memoized function. |
| L27 | **Type packs** (Luau-style `T...` generic pack parameters) plus intrinsic-checked stdlib APIs **(user, R1)** | `pairs`, `select`, `pcall`, event payloads and constructor forwarding become typeable. |
| L28 | Type-based fast lowerings (no `tostring` in interpolation, `?.` as `and`, `??` as `or`) only in **strict** mode **(user, R1)** | Basic-mode types may be wrong at runtime, so basic mode always uses the safe forms. |
| L29 | No methods outside class bodies (E2003 with a quick fix) **(user, R1)** | Classes are sealed. |
| L30 | `type`/`interface` may be declared anywhere (block-scoped). `class`/`enum` only at module top level **(user, R1)** | |
| L31 | v1 includes **getters/setters, overloads in classes, typed coroutines, `setmetatable` typing** **(user, R1)** | Only classes with properties pay for an `__index` function. |
| L32 | `local addonName, ns = ...` is typed `(string, AddonNamespace)`. `AddonNamespace` is an interface projects extend with `declare interface` (declaration merging) **(user, R1)** | Typed classic namespace sharing. |
| L33 | Top-level `return` is an error in modules and allowed in scripts **(user, R1)** | |
| L34 | Generic variance: covariant in basic mode, invariant for mutable positions in strict mode **(user, R1)** | Pragmatic by default, sound in strict. |
| L35 | A constructor's parameter may be a **parameter property**: `public`/`protected`/`private` and/or `readonly` before its name declare an instance field of that name and type, assigned from the argument first (base class: before the field initializers; derived: right after `super(…)`); with a default, the field is always set. A field declared twice (a property among them) is E3046. A `readonly` field is assignable only in its initializer or its own class's constructor (methods and subclasses' constructors: E2010) **(user, M9)** | Constructor injection, the pattern SuuUI's classes use for testable dependencies (`constructor(private combat: CombatState = live, private fault: Reporter = log)`), would otherwise repeat each dependency as a field, a parameter and an assignment, as TypeScript's parameter properties avoid. Writing them showed `readonly` fields were assignable in any method of the class. |
| L36 | `ClassOf<T>` for a type parameter binds `T` from the table passed: a class's (its instance type, type arguments `any`) or an enum's (the enum); unbound it is `any`, inside the body a table. A generic predicate binds its type parameters from every argument. The expected type binds a type parameter only where the arguments left it open or their binding fits it; a binding that does not fit stays **(user, M9)** | `wowlua:reflect` promised typed results (`isInstance` narrowing, `enumFrom` → `Direction?`) that its `any` signatures could not give: `ClassOf<T>` on a type parameter was a plain `table` and bound nothing. SuuUI's `reflect.enumFrom(Kind, raw)` met it. Unioning the expected type into a binding named the target in the error (`nil \| boolean \| number` for `local b: boolean = id(5)`). |
| L37 | Every parameter is in scope in a parameter's default, as in Lua: reading the parameter itself or a later one there is E1004 (it is not set yet), also when its name shadows an outer one; a function literal in the default may read any **(user, M9)** | The checker resolved such a name to the outer variable while the compiled code read the parameter: SuuUI's `constructor(private settings: ModuleSettings = settings.store)` type-checked against the `settings` module and failed at load with "attempt to index local 'settings'". JavaScript makes the same reads a ReferenceError. |
| L38 | `assert` is declared as Lua's is: `assert<T, A...>(value: T, ...: A...): (T, A...)`, every argument returned; the first result keeps its truthy narrowing **(user, M9)** | Declared returning `T` alone, `return assert(x, "msg")` in a function declared to return one value passed the message on unseen: SuuUI's test helper `btn(m, key)` gave `mock.click(btn(m, "bags"))` a second argument, a mouse button "bags", and the click went nowhere. Eight such returns in SuuUI. |
| L39 | A type assertion also compares the expression's type with its `nil` left out: `T? :: U` is allowed when `T :: U` is **(user, M9)** | `tabs :: Button[]` for a `TabButton[]?` (an optional field, cast to a supertype in a test) was E2015: with `nil` the union fit neither way and was not a table. Only the expression's side drops `nil`, so `string? :: number` stays an error in basic mode (where `nil` fits every type), and a cast to an optional type keeps its old rule. |
| L40 | Overload resolution expands a last argument that gives several values (a call, `...`): its values fill the parameters from its position on, any number of them (a `...T`) as many as remain **(user, M9)** | `tex:SetTexCoord(unpack(coords))` was E2012: the call counted as one argument, and neither the four- nor the eight-number overload took one. A call of a function that is not overloaded already expanded it. |
| L41 | A call receiving a field path (`a.b` as an argument or a receiver) invalidates the narrowing of the paths below it (`a.b.c`), not of `a.b` itself or its siblings; receiving the root still invalidates all of its paths **(user, M9)** | The call gets the field's table, not the one that holds the field, so it cannot reassign `a.b` (no more than any call that does not receive `a`, which already keeps the narrowing). Before, `self.icon = parent:CreateTexture(); self.icon:SetTexture(x); self.icon:SetSize(1, 1)` failed on the third line in strict mode: the second forgot every narrowed field of `self`. |
| L42 | A widget class has `C.adopt(frame, …)`: the class built on an existing frame of its native type, the root's `super(…)` taking that frame instead of calling `CreateFrame` **(user, M9)** | Frames the game makes (a secure group header's unit buttons, a pool's template frames) could not become widget-class instances: `new` always creates. SuuUI's unit frames are mixed into header buttons as well as made fresh. The runtime hands the frame to the root by class, so a construction of another class inside the constructor's arguments does not take it. |
| L43 | `FontString`, `Texture`, `Line` and `MaskTexture` are widget types too: a widget class may extend them, built with `adopt` on the region its frame made; it has no `new` **(user, M9)** | SuuUI's text style (`Text`) is a mixin on font strings and could not become a class: a class could not extend a region, and `super(…)` creates with `CreateFrame`, which makes no regions. `adopt` (L42) supplies the region. |
| L44 | A constrained type parameter keeps a literal argument, and any parameter keeps the declared type of a value typed elsewhere (a name, a field, a call's result: unions of literals included) (`E extends EventName` binds `"UNIT_HEALTH"`, not `string`) and fits where its constraint (a union) is expected; `EventArgs<E>` with a declared name is that event's or message's payload in any function, and `...: EventArgs<M>...` declares a sender; elsewhere it is any values. A union of more than twelve members shows its first eight in messages **(proposal, M9)** | SuuUI's event bus could not type its handlers: `EventArgs` was `any` outside `wowlua:events`, and an unconstrained-style widening turned the name into `string`, so the constraint failed and the payload was lost. The full `EventName` union made an E2014 message about 100 KB long. |
| L45 | `keyof T` and `T[K]` (indexed access), as in TypeScript, for table types: a field name union and a field's type; kept while a type parameter is not bound, worked out when it is; a generic class's method reads the class's arguments in its constraints, and a class base with `typeof` is worked out where the file reaches the class **(user, M9)** | The user asked SuuUI to use no `any`; a module's `M:Get("line")` read every setting as `any`, because nothing could say "the type of the default named by the key". With `Get<K extends keyof D>(key: K): D[K]`, a module's defaults type its settings. |
| L46 | In a declared class, `Self` is the receiver's type where a member is read (a hidden type parameter bound per access); in a wowlua class it stays the class **(proposal, M9)** | The game's script handlers take `self: Self`; on a widget class's instance (`class Toggle extends Button`), the handler's `self` was a `Button`, so its fields were unknown and its annotation `self: Toggle` was refused. Declared classes have no bodies to check, so a parameter is safe there. |
| L47 | Inside a closure, an unannotated local that a closure assigns (or captured and assigned later) is the union of its narrowed types where functions are made in its scope and the values assigned after one is made or from a function; a `nil` (or bare) declaration adds no `nil` before its first value. The file is checked again with the previous pass's unions until they hold (at most four passes; what still changes is `any`) **(user, M9: no implicit `any`)** | Such locals read as `any`, the largest source of implicit `any` in SuuUI (a flag saved and restored, a counter, a cache filled lazily): their final type depends on the assignments in the closures themselves (`count = count + 1`), so one pass in source order cannot know it. Narrowed types at creation, not the whole union of assignments: `local pos = get(); if not pos then return end … defer(function() pos.x end)` keeps `pos` non-nil. |
| L48 | A table literal argument of a generic call holding a function with an unannotated parameter is inferred on trial (its diagnostics dropped) to bind the type parameters, then checked against its parameter with them bound; an expected result of `any` or `unknown` binds no type parameter **(user, M9: no implicit `any`)** | `segmented({ options = { { value = 5, … } }, onChange = function(v) … end })` reported E2050 for `v` (a callback in a table had no type before the binding), and in `print(seg(…))` the `any` of `print`'s parameter replaced the binding the options gave. |
| L49 | Strict mode: a named field of an array other than `n` is E2003, as is a number literal key a record with fields doesn't have; reading another key of a table type without an indexer (a record, a class, a `{}` filled later) stays `any` and is W2063 **(user, M9: no implicit `any`)** | `art[1]` of a record and `list.atlas` of an array read `any` unseen (SuuUI's tests kept passing `nil` comparisons after a type changed). A table literal mixing a list and named entries infers as the list (the named ones dropped), so those need their type written. An empty `{}` stays `any`: tables filled later with dynamic keys (`setmetatable({}, …)`) are typed `{}`. |
| L50 | `self` in the arguments of `super(…)`, in a function written there too, is E3001 ("used before `super(...)`") **(proposal, M9)** | SuuUI's inventory passed `onClose = function() … self.onClose … end` to its panel's `super`: the function's `self` was not the window the constructor made (a widget class's `self` exists once `super` has created the frame), so its close button never called the inventory's `onClose`; nothing reported it. |
| L51 | A member a widget class doesn't declare (read, set or called), which the game's frames' openness lets through as `any`, is W2063; the game's own frames stay open without a report **(user, M9: no implicit `any`)** | SuuUI stored about 900 undeclared fields on its widget classes' instances (`panel.ok`, `book.next.secure`), all `any`, unseen: plain classes report them (E2003), widget classes inherited the frames' `[string]: any`. An error would break code that works; the lint shows them to projects that keep `any` out. |
| L52 | Without an expected type, an empty table literal after `or` or `??` takes the type of the value before it (its truthy part) when it fits that type: `opts or {}` with `opts: Options?` is `Options` **(user, M9: no implicit `any`)** | It was the union with an empty record, whose fields read as `any`: SuuUI's `local d = data or {}` lost every field's type (a dozen of its UI files read their options so). |
| L53 | Reading a record without an indexer with a key typed as string literals (`color[k]` with `k: keyof Colors`) gives those fields' types, as `Colors[K]` does; a key typed `string` still reads `any` **(user, M9: no implicit `any`)** | It read `any` (W2063) even where the key could only name a field, so code keyed by `keyof T` lost the fields' types. |
| L54 | `select(n, …)` with a whole number literal `n` (1 or more) of the global `select` gives the types of the values from the n-th on; other forms keep the declaration (`...any`) **(user, M9: no implicit `any`)** | The declaration can't drop the first `n - 1` values of a pack, so `select(4, GetShapeshiftFormInfo(i))` read `any`; SuuUI reads API results so. |
| L55 | A type parameter left unbound by a generic call's other arguments, named in the results of a callback parameter, is bound from what a function expression passed there returns when it has no return annotation; a result type not known yet (`...any`) binds nothing **(user, M9: no implicit `any`)** | `pcall(function() return x end)` gave `(boolean, any)`: the expression's results were never inferred into `R...`, and a callback without parameters bound `R...` to `any` in the first pass. `pcall` and `xpcall` give `any` after the boolean where the function never returns (`never`) or returns nothing: there the values are only what it raised (`select(2, pcall(error, "x"))`). |
| L56 | *(Replaced by L86.)* A class's method without a return annotation returns `any`: the class's method types are known before their bodies are checked, so its returns can't be inferred as a function's are; W2063 reports the values read from it **(proposal, M9)** | The inference table promised the union of the returns for every function; methods never had it. Inferring them would need the class's bodies checked before any use of the class. |
| L57 | A class's field and method types are worked out again where the checker reaches the class when its file has resolved a `typeof` alias before it, so an annotation using the alias reads its type **(user, M9: no implicit `any`)** | Class members are typed before the file is checked, when a `typeof` alias is still `any`: SuuUI's `api: ResourceApi` (a record of `typeof(UnitClass)` and the like) read every API result as `any` inside the class's methods, while the same alias was typed in functions. |
| L58 | A type alias whose body is a table type and that refers to itself (directly or through other aliases) is a named type with the table's fields as members, which values match exactly as they match the table **(user, M9: no implicit `any`)** | Aliases were expanded where used, so a self-reference read as `any`: SuuUI's `TrackerEntry` (a group's `members?: TrackerEntry[]`) made every member `any`, though §2.3 allows the alias. A named type ends the expansion without changing how table values match it. |
| L59 | A table assigned to an unannotated local that fits the local's type so far gives its empty `{}` fields that type's field types; its other fields stay **(user, M9: no implicit `any`)** | The lazily filled cache (`local p = byKey[k]; if not p then p = { seen = {}, ids = {} }; byKey[k] = p end`) read `p.seen[id]` as `any`: the narrowed type was the literal's, whose `{}` has no indexer. An empty table carries no type of its own, so taking the local's is never less precise; the value's own fields are kept so a wider value still reads its extra fields. |
| L60 | A field read on an intersection takes the first part that has the field, not counting a part that reads it as `any`; a key read takes the first part with numbered values or an indexer **(user, M9: no implicit `any`)** | SuuUI's colour tokens are `number[] & { hex: string }`: `color.hex` read as `any` because the array part, asked first, answered `any` for a named field, and `color[1]` as `any` because key reads didn't look into intersections at all. |
| L61 | A literal assigned to an unannotated local whose type so far has that literal (`false` of `T \| false`) keeps its literal type; other literals widen as in `local` **(user, M9: no implicit `any`)** | SuuUI's convergences cache a spot's world place as `World \| false` (false: none): `local w = cache[spot]; if w == nil then w = false … cache[spot] = w end` widened the `false` to `boolean`, so the store back was E2001 and `w or nil` read `true \| World`; an annotation was the only way out |
| L62 | `typeof(expr)` in a function's parameter and result annotations is typed where the function stands, as in a `local`'s annotation **(user, M9: no implicit `any`)** | Only `local` annotations and aliases inferred their `typeof` parts: in a signature `typeof(colors)` read as `any`, so SuuUI's `coin(token: keyof typeof(T.color))` took any value and `T.color[token]` was `any` |
| L63 | Where an `unknown` value is falsy (the left of `and`, the false branch of a test) it is `false \| nil`; `any` stays `any` **(user, M9: no implicit `any`)** | `unknown` stayed whole there: `done and true or false` with `done: unknown` (a pcall's result) was `unknown \| boolean`, not a `boolean`, so SuuUI's Legacy steps needed a cast to fit `done?: boolean` |
| L64 | An unannotated local initialized with a `::` assertion or a `?.` read keeps that value's type, as it already did for names, fields, indexes and calls; only literals written there widen **(user, M9: no implicit `any`)** | `local point = (vp .. horiz) :: FramePoint` widened the assertion to `string`, so SuuUI's ActionBars could not hand the point on as a `FramePoint` without annotating the local |
| L65 | An unannotated local a loop body assigns keeps its type at the loop start (its type before the loop, joined with what the paths back bring, tried at most twice) and after the loop, with its `break` paths joined; a declared local that leaves its narrowing no longer makes the others in the loop forget theirs **(user, M9: no implicit `any`)** | Every unannotated local a loop assigned read as `any` in the loop and after it: `local header = C_QuestLog.GetHeaderIndexForQuest(id)` walked up the log in a `for` loop, and `C_QuestLog.GetInfo(header)` after it took an `any`, so SuuUI's ObjectiveTracker needed an annotation. Reads after such loops are now checked: a search loop's result is `T?`, not `any`. |
| L66 | `import internal` binds a module's exports too, with their export types, as file-level names **(user, M9: no implicit `any`)** | `import internal M, minimapPlace from "/Units/Marks"` read the `export function minimapPlace` as `any`: the internal names listed plain `local`s and `function`s only, so an exported one was missing; a plain `import` of it was typed. |
| L67 | A function written in a `hook(…)` or `hookScript(…)` call takes its parameter types from what it hooks: a global function's, a method's with the receiver first, a script's handler for `hookScript` (the overload `HookScript` has for that script) **(user, M9: no implicit `any`)** | `wowlua:hooks` takes `any` for its arguments, so every hook callback's parameters were implicit `any` (W2063) unless annotated; SuuUI has hundreds. The types come from the declarations the W8040 check already reads; a generic or undeclared target leaves the callback as before. |
| L68 | W1004 also reports a `local function` named like a local of the same block **(user, M9)** | A test file's `local function sidebar()` helper was followed by `@test(…) local function sidebar()`; inside the test, `sidebar()` called the test itself, endlessly. Re-binding a plain `local` (`local x = f(x)`) stays unreported. |
| L69 | A class that extends a name only `import type` brings is error E3008: the type is a class, but nothing of it exists at run time to extend **(user, M9)** | SuuUI's `import type ItemSlot from "/UI/Inventory"` then `class AttachSlot extends ItemSlot` checked clean and failed at load ("attempt to index global 'ItemSlot'"). A name imported both ways is a value. |

## Toolchain

| # | Decision | Rationale |
|---|----------|-----------|
| T1 | Spec as Markdown chapters in the repository **(user)** | Versioned with the compiler. |
| T2 | Compiler in **Rust**, one binary for compiler, package manager and tooling **(user)** | |
| T3 | Support **all WoW flavors**. Split per-flavor compilation by default **(user)** | Per-flavor type checking and dead-code removal. |
| T4 | Manifest is **strict JSON** (`wowlua.json`) with a `$schema` key **(user)** | Tool-friendly. Editors get completion through the JSON schema. |
| T5 | Dependency sources: git, local path, archive URL, and a wowlua registry (later phase) **(user)** | |
| T6 | Publish targets: CurseForge, Wago, WoWInterface, GitHub Releases **(user)** | The major WoW addon sites. |
| T7 | Minification levels are **user-defined in the project**, selectable per profile and per publish target **(user)** | Different platforms allow different amounts of minification. |
| T8 | Default with no configuration: release is **bundled + `strip`** (comments, whitespace and safe syntactic simplifications), with no renaming. Dev is unminified. **(user, amended in review R1)** | Fast loading, readable code. |
| T9 | Dev builds: one file per module with **line numbers preserved**. Release: bundled. **(user)** | In-game errors in dev builds point at the right source line with no tooling. |
| T10 | Libraries and the stdlib are embedded as a **private, tree-shaken copy per addon** **(user)** | No cross-addon version conflicts. |
| T11 | Additional tooling: test runner, language server, formatter, trace decoder **(user)** | |
| T12 | WoW API types: generated from **Blizzard's API documentation**, enriched with additional information from Ketho's vscode-wow-api (MIT) **(user)** | Most accurate, per-flavor, typed event payloads. |
| T13 | Warning W6010 when a publish target uses a renaming minification level **(user)** | Blizzard's AddOn policy forbids hidden or obfuscated code. |
| T14 | **One zip for all flavors**, tagged with every flavor's game version per site. Per-target `split-flavors` available. **(user)** | Packager convention, supported by CurseForge and Wago. |
| T15 | Ecosystem compatibility: import existing TOC and `.pkgmeta`, optionally keep `.pkgmeta`, support BigWigs packager keywords in passthrough files **(user)** | Easy migration of existing addons. |
| T16 | Resolver: PubGrub, one version per package per addon **(proposal)** | Everything is embedded into one AddOn. |
| T17 | `wowlua publish` requires a clean tree and runs tests by default **(proposal)** | Safe releases. Both can be overridden with flags. |
| T18 | Build output is validated (TOC references, Lua 5.1 reparse, Lua limits, XML) before writing **(proposal)** | Guarantees a working AddOn. |
| T19 | **TOC layout `auto`**: a single TOC with comma-separated interfaces and inline `[AllowLoadGameType …]` directives when every targeted client supports it, otherwise per-flavor TOC files **(user)** | Blizzard's direction, fewer files. The fallback keeps frozen clients working. |
| T20 | Flavor IDs are **Blizzard game types** (`standard`, `camelot`, `mists`, `cata`, `wrath`, `tbc`, `vanilla`), with friendly aliases in the manifest **(user)** | They name rulesets rather than clients, and match TOC directives. |
| T21 | WoW API types are **pre-generated** in CI and published as `wow-api-<flavor>` packages **(user)** | Convenience. Blizzard's documentation has no explicit license, and the project owner accepted publishing derived type information. |
| T22 | `wowlua:locale`: JSON files per locale, typed named placeholders, and **only the base locale plus the client's locale are loaded** (via `[AllowLoadTextLocale]` where every client supports it, otherwise a runtime guard) **(user, wording clarified in R1)** | Tool-friendly translations, compile-time checked, less memory. |
| T23 | Every minification level keeps **at least one line break per statement**, so source maps stay line-based and `wowlua trace` always works **(user, R1)** | WoW error messages have no column numbers. |
| T24 | Bundles **isolate modules**: each runs protected, errors go to `geterrorhandler()`, and later modules still load **(user, R1)** | Same behavior as separate files. |
| T25 | Publish builds go to `dist/targets/<target>/`. Zips get a target suffix when targets differ **(user, R1)** | No collisions between targets. |
